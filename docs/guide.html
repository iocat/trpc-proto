Direct mode

Complete quickstart

Direct mode is the recommended starting point. The included Node server receives gRPC-Web and invokes your real tRPC resolvers in-process. You do not need a second backend service.

Requirements and installation

  • Node.js 22 or newer
  • tRPC 11
  • Zod 4
  • TypeScript 5.9 or newer
Terminal 
npm install @trpc/client @trpc/server @trpc-proto/runtime @grpc/grpc-js zod
npm install --save-dev @trpc-proto/plugin typescript tsx

1. Define an explicit contract

Give the router a protobuf package and add an explicit output schema to every procedure. The generated schema keeps field numbers stable across generations.

src/router.ts 
import { initTRPC } from '@trpc/server';
import type { ProtoMeta } from '@trpc-proto/runtime';
import { z } from 'zod';

const t = initTRPC.meta<ProtoMeta>().create({
  defaultMeta: {
    proto: {
      package: 'example.v1',
      schemaPath: 'generated/schema.ts',
    },
  },
});

const User = z
  .object({
    id: z.string(),
    name: z.string(),
  })
  .meta({ protoMessageName: 'User' });

export const appRouter = t.router({
  getUser: t.procedure
    .input(z.object({ id: z.string() }))
    .output(User)
    .query(async ({ input }) => {
      return { id: input.id, name: 'Ada' };
    }),
});

export type AppRouter = typeof appRouter;

2. Generate the protobuf contract

@trpc-proto/plugin installs the local trpc-proto executable, so generate the contract with one npx command:

Terminal 
npx trpc-proto generate \
  --router src/router.ts \
  --export appRouter \
  --out generated

3. Start the direct gRPC-Web server

Use serveGrpcWeb when the runtime should own the HTTP listener and its shutdown lifecycle.

src/server.ts 
import { serveGrpcWeb } from '@trpc-proto/runtime';
import { protoSchema } from '../generated/schema.js';
import { appRouter } from './router.js';

const server = await serveGrpcWeb({
  mode: 'direct',
  router: appRouter,
  schema: protoSchema,
  address: '127.0.0.1:50052',
  cors: {
    allowedOrigins: ['http://localhost:5173'],
  },
});

console.log(`gRPC-Web listening on http://${server.address}`);
$npx tsx src/server.ts

Use createDirectGrpcWebHttpHandler when an existing Node HTTP server already owns routing. The handler returns true only when it writes the response.

src/http-server.ts 
import http from 'node:http';
import { createDirectGrpcWebHttpHandler } from '@trpc-proto/runtime';
import { protoSchema } from '../generated/schema.js';
import { appRouter } from './router.js';

const handleGrpcWeb = createDirectGrpcWebHttpHandler(appRouter, {
  schema: protoSchema,
  cors: {
    allowedOrigins: ['http://localhost:5173'],
  },
});

const server = http.createServer(async (request, response) => {
  if (await handleGrpcWeb(request, response)) return;

  // Continue with the application's existing routes.
  response.writeHead(404);
  response.end();
});

server.listen(50052, '127.0.0.1');

4. Create the browser client

Import the router as a type only. Importing the router value makes the bundler traverse resolver modules and can pull Node-only or database code into the browser build.

src/client.ts 
import { createTRPCClient } from '@trpc/client';
import { grpcWebLink } from '@trpc-proto/runtime/web';
import { protoSchema } from '../generated/schema.js';
import type { AppRouter } from './router.js';

export const client = createTRPCClient<AppRouter>({
  links: [
    grpcWebLink<AppRouter>({
      // Required: the generated runtime schema.
      schema: protoSchema,

      // Optional string. Default: '' (same origin).
      url: 'http://127.0.0.1:50052',

      // Optional: 'raw' | 'base64'. Default: 'base64'.
      encoding: 'raw',

      // Optional: true | false. Default: false.
      compress: false,

      // Optional: false | true | { maxItems?: number }. Default: false; maxItems: 100.
      batch: { maxItems: 100 },

      // Optional AuthConfig. Default: undefined.
      auth: {
        // Optional string or sync/async getter. Default: undefined.
        token: () => localStorage.getItem('accessToken') ?? undefined,
        // Optional metadata record or sync/async getter. Default: undefined.
        metadata: {},
        // Optional string. Default: 'authorization'.
        header: 'authorization',
        // Optional string. Default: 'Bearer'; use '' for a raw token.
        scheme: 'Bearer',
      },

      // Optional CallInterceptor[]. Default: [].
      interceptors: [],
    }),
  ],
});

const user = await client.getUser.query({ id: '1' });

Concepts

Start with the mental model

trpc-proto treats the exported tRPC router as the source of truth. The generator evaluates that router, inspects its Zod input and output schemas, validates that every shape has a faithful protobuf representation, and writes two generated files.

SOURCEappRouterZod schemas
→
GENERATEtrpc-protovalidate first
→
CONTRACT.proto + schema.tsstable field IDs

The .proto is the language-neutral contract. The generated schema.ts is data used by the TypeScript transports to encode and route calls without importing the server router into a browser bundle.

Strict by design.

Unsupported schemas fail generation with procedure paths and reasons. The generator does not silently replace them with lossy fallback types.

Contract output

Understand the generated files

File Used by Responsibility
example_v1.proto Native tooling Service, message, enum, field, and stream declarations for normal protobuf code generators.
schema.ts TypeScript runtime Data-only schema for protobuf encoding, decoding, routing, and stable field-number caching.

Keep the generated files in version control

Commit both generated/schema.ts and the generated .proto. The schema file is runtime data and generator state: when you delete a field, it preserves the old number so the next .proto marks it as reserved. Keeping both files prevents accidental wire-number reuse and makes contract changes reviewable.

Regenerate after contract changes.

Inputs, outputs, procedure paths, package metadata, and explicit protobuf names all affect generated output. Review and commit both files together.

Runtime architecture

Choose a deployment mode

Recommended

Direct mode

The Node gRPC-Web server and appRouter run in one process. Requests are protobuf-decoded and dispatched to the router without a native gRPC network hop.

  • Requires router and schema
  • Supports tRPC middleware and createContext
  • Best when TypeScript owns the implementation
Polyglot

Forward mode

The Node process terminates gRPC-Web and forwards normal native gRPC to a separately hosted backend that implements the generated .proto.

  • Requires schema and backend
  • Works with Go, Rust, Java, and other gRPC stacks
  • The backend needs no gRPC-Web or batch endpoint

Managed server options

Option Mode Meaning
mode Both Required discriminator: 'direct' or 'forward'.
schema Both Generated protoSchema used to resolve methods and message types.
address Both HTTP/1.1 listen address. Defaults to 127.0.0.1:50052.
cors Both Optional exact-origin browser policy. CORS is disabled when omitted.
router Direct The real tRPC router value invoked in-process.
createContext Direct Optional sync or async context factory.
backend Forward Native gRPC address and optional TLS or mTLS credentials.

Forward to a native backend

src/gateway.ts 
import { serveGrpcWeb } from '@trpc-proto/runtime';
import { protoSchema } from '../generated/schema.js';

const gateway = await serveGrpcWeb({
  mode: 'forward',
  schema: protoSchema,
  address: '127.0.0.1:50052',
  backend: {
    address: '127.0.0.1:50051',
    credentials: { type: 'insecure' },
  },
  cors: {
    allowedOrigins: ['https://app.example.com'],
  },
});

await gateway.close();

The browser client is identical in both modes. Changing where procedures execute does not change the generated schema or client call syntax.

Secure an upstream connection

Forward mode defaults to an insecure grpc-js channel. For verified TLS or mTLS, provide certificate paths explicitly:

backend credentials 
backend: {
  address: 'api.internal.example:50051',
  credentials: {
    type: 'mtls',
    caCertPath: '/run/secrets/upstream-ca.pem',
    serverNameOverride: 'api.internal.example',
    clientIdentity: {
      certPath: '/run/secrets/client-cert.pem',
      keyPath: '/run/secrets/client-key.pem',
    },
  },
}

Omit clientIdentity for one-way TLS. The runtime checks the configured certificate files periodically and uses valid replacements for new connections.

Client configuration

Configure grpcWebLink

Option Default Behavior
schema Required The generated runtime schema.
url '' Request origin. Empty means the current browser origin.
encoding 'base64' 'raw' sends binary frames; 'base64' uses gRPC-Web text bodies.
compress false Gzip-compress each request message before framing.
batch false true or { maxItems } batches queries and mutations.
auth None Bearer token and additional metadata, provided statically or by async getters.
interceptors [] Client call interceptors around encoding and transport.

compress controls request messages only. grpcWebLink always advertises gzip response support, and the built-in handlers automatically gzip each unary or streaming response message, in order, when negotiated. Clients that do not advertise gzip receive uncompressed response frames.

Raw versus base64 bodies

Setting Content type HTTP body
'raw' application/grpc-web+proto Binary length-prefixed frames.
'base64' application/grpc-web-text+proto Base64 representation of the same frames.

Base64 is the compatibility-oriented default. Raw mode avoids base64 expansion when your browser, proxy, and deployment path accept binary gRPC-Web bodies.

Authentication and metadata

client auth 
grpcWebLink<AppRouter>({
  schema: protoSchema,
  auth: {
    token: async () => session.accessToken,
    metadata: () => ({ 'x-trace-id': crypto.randomUUID() }),
  },
})

The default token header is authorization and the default scheme is Bearer. Use scheme: '' for a raw value. Custom browser headers must also be permitted by the server's CORS policy.

Call behavior

Batching, subscriptions, and cancellation

Batch queries and mutations

browser client 
grpcWebLink<AppRouter>({
  schema: protoSchema,
  encoding: 'raw',
  batch: { maxItems: 100 },
})
  • Calls queued in the same microtask are grouped.
  • Queries and mutations use separate batches.
  • Procedures inside a batch execute concurrently.
  • Each item keeps its own encoded result or application error.
  • maxItems defaults to 100 and only controls client-side request splitting.
  • Batching is supported in both direct and forward modes.

Declare a server-streaming subscription

router subscription 
import { zAsyncIterable } from '@trpc-proto/runtime';

const appRouter = t.router({
  onUserChange: t.procedure
    .input(z.object({}))
    .output(zAsyncIterable({ yield: User }))
    .subscription(async function* ({ signal }) {
      for await (const user of userChanges({ signal })) {
        yield user;
      }
    }),
});

Subscriptions always use the normal streaming transport, even when batching is enabled. Closing or aborting the browser request cancels the corresponding forwarded backend call. A stream emits zero or more data frames and must finish with a gRPC status trailer.

Contracts that fail generation

  • A procedure without an explicit output schema
  • Chained input parsers
  • Open object unions instead of a discriminated union
  • Literal unions that mix value types
  • Numeric literals that mix integer and floating-point values
  • Maps with non-scalar key types
  • Invalid protobuf names
  • Unsupported Zod types or tRPC-only values with no protobuf representation

Generation prevalidates the router and reports every discovered issue with its procedure path. Fix the contract at the router boundary rather than expecting a wire-format approximation.

Browser boundary

CORS, metadata, and security

CORS is disabled when the cors option is omitted. When enabled, origins are exact serialized strings—scheme, host, and port must match.

CORS options 
cors: {
  allowedOrigins: ['https://app.example.com'],
  additionalAllowedHeaders: ['x-trace-id'],
  maxAgeSeconds: 600,
}

The default preflight allowlist includes accept, authorization, content-type, grpc-timeout, x-grpc-web, and x-user-agent. Add only application-specific headers through additionalAllowedHeaders.

CORS is not authorization.

Non-browser callers can omit or forge Origin. Enforce authentication and authorization with tRPC middleware, bearer metadata, mTLS, or another real credential boundary.

Forward mode filters HTTP transport and gRPC-Web control headers before creating grpc-js metadata. Application headers, including authorization, grpc-timeout, and allowed custom headers, cross the gateway as string metadata.

Diagnostics

Understand errors and trailers

Browsers cannot reliably read HTTP/2 trailing headers through Fetch, so gRPC-Web puts the final gRPC status in a trailer frame inside the response body. Successful unary and streaming responses end with grpc-status: 0.

Condition HTTP Client result
Successful call 200 Data frame(s), then status 0.
Backend gRPC error 200 Final trailer carries the backend status and message.
Malformed framed request 200 Status 13, INTERNAL.
Rejected CORS origin or header 403 The backend is not called.
Rejected preflight method 405 POST is reported as allowed.

A final status is mandatory. Missing, malformed, or out-of-range statuses become GrpcWebError with status UNKNOWN. If an intermediary returns no gRPC status, the client applies the standard HTTP-to-gRPC fallback mapping.

Make protobuf calls observable while developing

Browser Network panels show framed protobuf bytes rather than friendly JSON. Put tRPC's loggerLink() before grpcWebLink to log decoded inputs, results, and failures at the client boundary.

Beyond browsers

Use native gRPC from Node

A Node tRPC client can call a native gRPC server directly with grpcLink:

native client 
import { createTRPCClient } from '@trpc/client';
import { grpcLink } from '@trpc-proto/runtime';

const client = createTRPCClient<AppRouter>({
  links: [
    grpcLink<AppRouter>({
      schema: protoSchema,
      address: '127.0.0.1:50051',
      auth: { token: process.env.AUTH_TOKEN },
    }),
  ],
});

A TypeScript router can also serve native gRPC clients with serveGrpc. Use bindRouter when an existing grpc-js server owns service registration.

native server 
import { serveGrpc } from '@trpc-proto/runtime';

const server = await serveGrpc(appRouter, {
  schema: protoSchema,
  address: '127.0.0.1:50051',
});

await server.close();

Common problems

Troubleshooting

Generation says a procedure has no output schema

Add an explicit .output(zodSchema). tRPC can infer an output from a resolver, but protobuf generation needs an inspectable wire contract.

Server-only dependencies appear in the browser bundle

Import AppRouter with import type and import protoSchema for runtime data. Do not import the appRouter value into browser code.

The browser receives a CORS 403

Match the browser's exact serialized origin in allowedOrigins. If the request sends custom metadata headers, add their lower-case names to additionalAllowedHeaders.

A call returns UNIMPLEMENTED

Regenerate both contract files and confirm that the browser, gateway, and backend use the same generated revision. Forward mode rejects paths absent from protoSchema before contacting the backend.

Field numbers changed unexpectedly

Configure defaultMeta.proto.schemaPath, keep the generated schema.ts in version control, and do not delete it before regeneration.
